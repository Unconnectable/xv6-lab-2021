# 内存管理与地址转换以及页表的示例

## 系统配置

- **物理内存大小**: 16 KB
- **页面大小 (Page Size)**: 4 KB
- **运行的进程**: 进程 A 和进程 B

## 物理内存布局

| 物理地址范围 | 内容          |
| ------------ | ------------- |
| 0 - 4 KB     | 进程 A 的数据 |
| 4 - 8 KB     | 进程 B 的数据 |
| 8 - 12 KB    | 空闲          |
| 12 - 16 KB   | 操作系统内核  |

## 进程 A 的虚拟地址空间

| 虚拟地址范围 | 映射的物理地址 |
| ------------ | -------------- |
| 0 - 4 KB     | 0 - 4 KB       |
| 4 - 8 KB     | 8 - 12 KB      |

## 进程 B 的虚拟地址空间

| 虚拟地址范围 | 映射的物理地址 |

| ------------ | -------------- |
| 0 - 4 KB | 4 - 8 KB |
| 4 - 8 KB | 12 - 16 KB |

## Page Table 的作用

每个进程都有自己的 Page Table,用于将虚拟地址映射到物理地址.每一个 Process 的也 Page Table 让他们拥有不重合的物理内存,使得相互之间不能访问,这就实现了内存隔离.

### 进程 A 的 Page Table

| 虚拟页号 (VPN) | 物理页帧号 (PPN) |
| -------------- | ---------------- |
| 0              | 0                |
| 1              | 2                |

### 进程 B 的 Page Table

| 虚拟页号 (VPN) | 物理页帧号 (PPN) |
| -------------- | ---------------- |
| 0              | 1                |
| 1              | 3                |

## 地址转换过程

### 进程 A 访问虚拟地址 0x1000（位于虚拟页 0）

1. CPU 的 MMU 查询进程 A 的 Page Table,发现虚拟页 0 映射到物理页帧 0.
2. 物理地址 = 物理页帧号 × 页面大小 + 偏移量 = 0 × 4 KB + 0x1000 = 0x1000.
3. 最终访问的物理地址是 **0x1000**.

### 进程 B 访问虚拟地址 0x2000（位于虚拟页 1）

1. CPU 的 MMU 查询进程 B 的 Page Table,发现虚拟页 1 映射到物理页帧 3.
2. 物理地址 = 物理页帧号 × 页面大小 + 偏移量 = 3 × 4 KB + 0x2000 = 0x3000 + 0x2000 = 0x5000.
3. 最终访问的物理地址是 **0x5000**.

### 抽象物理资源

1. process 抽象了 cpu,cpu 运行一个进程一段时间比如 100ms,
   然后运行另一个进程,不会存在多个进程同时用一个 cpu,这是复用
2. exec 抽象了内存
3. file 抽象了磁盘,app 不被允许直接在磁盘上读取东西,但是可以通 files 进行文件交互

当需要和内核交互的时候,执行的命令是需要经过检查的.
比如 fork 实际上是`ecal system call fork`,然后把 systemcall 的代表的参数 fork,进行检查然后实现

### 宏内核：

一种可能是整个操作系统驻留在内核中,这样所有系统调用的实现都在监督者模式下运行把.例如 xv6,linux

### 微内核：

多个字模块分割开,尽量少的在 kernel,虚拟内存,文件管理等在 usr.内核接口由一些低级函数组成,用于启动应用程序、发送消息、访问设备硬件等.mircro 不共享资源,难以实现高性能
